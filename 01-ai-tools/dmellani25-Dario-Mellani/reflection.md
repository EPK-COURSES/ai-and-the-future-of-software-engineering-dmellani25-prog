# Personal Reflection — AI Coding and Development Tools
**Topic 0 — SWE101 Assignment**

---

When I started this research, I expected to find a straightforward story: AI tools make developers faster. What I found was more complicated, and honestly more interesting.

## What Surprised Me Most

The number that surprised me the most was the trust gap. Only 33% of developers say they trust AI-generated code. Meanwhile, 90% of developers are using AI tools regularly. That means the vast majority of developers are using tools they do not fully trust. At first that seemed contradictory. But after thinking about it, I think it reflects something mature: they use these tools as a starting point, not a final answer. The problem is that a significant portion of developers are not always verifying the code before committing it. That creates invisible technical debt and security risk that may not surface until later in a project — or in production.

The statistic about 29.1% of AI-generated Python code containing potential security weaknesses was also striking. If I were accepting AI suggestions without understanding them, I might be shipping vulnerabilities without realizing it.

## What Concerns Me About AI in Software Engineering

My biggest concern is not about jobs — it is about understanding. If I rely on AI to generate code I do not understand, I can produce software without actually knowing how it works. That might be acceptable for small scripts. It becomes dangerous when I am building systems where correctness, security, or performance matters. The risk is that AI tools create a generation of developers who can produce code but cannot reason about it.

There is also a concern about entry-level developers specifically. Junior developers learn by doing repetitive tasks — writing boilerplate, fixing small bugs, reading existing code carefully. If AI handles all of that automatically, where does the deep learning happen? The industry seems to be replacing junior positions with AI, while still expecting new graduates to somehow develop the skills that come from doing junior work. That is a structural problem that the industry has not resolved yet.

## What Opportunities I See

The flip side is real too. If I learn to use these tools well, I can operate at a level of productivity that would have been impossible a few years ago. A single developer using Cursor or Claude Code effectively can build, test, and document things that previously required a small team. For someone just starting out, that is an opportunity to build a strong portfolio and demonstrate value faster than any previous generation of developers could.

I also see opportunity in the security and review space. As AI generates more code, organizations need engineers who can critically evaluate that code — not just check if it runs, but identify architectural problems, security weaknesses, and maintainability issues. That is a skill that requires deep understanding, and it is one that AI cannot do for itself.

## Which Skills I Think Will Remain Important

After this research, I am more convinced than ever that the skills that remain valuable are the ones AI tools struggle with:

- **Systems thinking:** Understanding how components interact across a full architecture, not just within a single file.
- **Security awareness:** Being able to read code critically and identify what could go wrong.
- **Critical evaluation:** Knowing when an AI suggestion is correct, when it is close-but-wrong, and when it is fundamentally misunderstanding the problem.
- **Communication:** Explaining technical decisions to non-technical stakeholders is something no AI tool replaces.
- **Problem decomposition:** Breaking a complex, ambiguous requirement into something a developer — or an AI agent — can actually act on.

## How My Opinion Changed

Before this research, I thought of AI coding tools as productivity shortcuts — useful but somewhat separate from "real" engineering. My view has shifted. These tools are becoming infrastructure, like version control or testing frameworks. Not using them effectively is beginning to look like a career choice that comes with real costs. At the same time, I now understand that using them without critical engagement is equally dangerous.

## How I Will Personally Adapt

My plan is to treat AI coding tools the same way I would treat a knowledgeable but imperfect colleague: use their output as a starting point, always review what they produce, ask why when something does not make sense, and never ship code I do not understand. I will prioritize building deep understanding of fundamentals — data structures, system design, security principles — so that I have the knowledge to evaluate AI output, not just accept it.

I will also start using tools like GitHub Copilot and Codeium (both have free tiers) during my studies, deliberately — not to skip learning, but to practice working alongside AI the way I will in professional environments.

The goal is to become the kind of engineer who makes AI tools more effective, not the kind who becomes dependent on them.
